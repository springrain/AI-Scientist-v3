# Model configuration

All research phases share the coding agent configured in `configs/models.local.yaml`.
This is the default configuration file and contains the complete settings;
`configs/models.yaml` is not required. Values are literal YAML; environment
interpolation and dotenv files are not used.

For example, create `configs/models.local.yaml`:

```yaml
agent: codex
model: your-model-name
base_url: https://your-endpoint.example/v1
api_key: your-api-key
reasoning_effort: high
api: openai-responses

literature:
  s2_api_key: ""
  openalex_api_key: ""
  openalex_email: ""
  openalex_base_url: https://api.openalex.org/works

review:
  model: your-review-model
  base_url: https://your-endpoint.example/v1
  api_key: ""

figures:
  enabled: false
  model: your-image-model
  audit_model: your-audit-model
  base_url: https://your-endpoint.example/v1
  api_key: ""
```

Edit this file when changing the model or endpoint, then start the next run.
There is no default-file merge or need to rebuild the agent image.

Then use the usual command:

```bash
agsci run examples/circpack
```

Task drafting, investigation, ablations, post-hoc analysis, paper writing, and
revision use the same agent settings. Final evaluation executes the evaluator
and has no model selection. Standalone stage commands also read this file.
The file takes precedence over legacy `agent.*` options, agent pools, Codex
profiles, and shell `--agent`/`--agent-model` arguments. Configure models through
the shared file, including when reproducing older examples that use those flags.

The endpoint must match the chosen agent:

| `agent` | Endpoint and configuration |
| --- | --- |
| `codex` | OpenAI Responses compatible; generates a private native provider with the configured URL, key, and model |
| `claude` | Anthropic Messages compatible, e.g. `https://api.anthropic.com`; main and subagent models use `model` |
| `gemini` | Gemini API compatible, e.g. `https://generativelanguage.googleapis.com` |
| `opencode`, `pi` | Set `api` to `openai-completions`, `openai-responses`, or `anthropic-messages` to match the server |
| `cursor` | Cursor's service only; `base_url` must be `https://api.cursor.com`, because custom provider endpoints are unsupported |

Model identifiers must exist at the configured endpoint. `reasoning_effort` is
optional (`low`, `medium`, `high`, `xhigh`); Gemini does not support it.

Native and Docker launches use isolated agent configuration directories.
Provider environment settings, subscription logins, and `.env` credentials are
not used to select or authenticate model calls. Missing configured API keys fail
before agent execution. Some CLIs require authentication in their process
environment; the launcher generates those values exclusively from this YAML.
Credentials are not included in command arguments or Hydra snapshots.

The shared `api_key` supplies the selected agent's native authentication:
Codex receives `CODEX_API_KEY`, Claude receives `ANTHROPIC_API_KEY`, and Gemini
receives `GEMINI_API_KEY`. These are generated by the launcher; configure their
value through `api_key` in this file.

Literature services are configured in the same file:

```yaml
literature:
  s2_api_key: your-semantic-scholar-key
  openalex_api_key: your-openalex-api-key
  openalex_email: you@example.com
  openalex_base_url: https://api.openalex.org/works
```

An empty or whitespace-only `s2_api_key` disables Semantic Scholar requests,
including its health check. Paper generation and revision skip directly to
OpenAlex; the standalone `s2_fetch.py` exits with a disabled-service message
without making a request. Set a non-empty key to enable Semantic Scholar.

`openalex_base_url` is the full search endpoint, normally
`https://api.openalex.org/works`. The retriever uses this URL directly without
appending a path and sends a non-empty `openalex_api_key` as the `api_key` query
parameter. Existing configurations that use `https://api.openalex.org` must add
`/works` to this setting. Get an OpenAlex key from your account's Settings → API key
([authentication documentation](https://help.openalex.org/api/authentication/)).
Keep the key in `openalex_api_key`, without adding it to `openalex_base_url`.
Host retrieval and standalone scripts read this YAML section.
Paper agents receive a private copy in their isolated home, allowing retrieval
inside containers without access to the host config. An empty or omitted
`openalex_api_key` sends no key; `openalex_email`, when set, supplies `mailto`.
Ambient `S2_API_KEY`, `OPENALEX_API_KEY`, and `OPENALEX_EMAIL` are ignored.

The optional final reviewer calls an OpenAI compatible API directly. Configure
its own text model in the same file:

```yaml
review:
  model: your-review-model
  base_url: https://your-review-endpoint.example/v1
  api_key: your-review-api-key
```

Both the pipeline review phase and `agsci review` use this section. Review is
still optional; enable it through the existing phase options.

Concept figures use the shared coding agent. Optional image enhancement and
visual audits have a separate OpenAI compatible API configuration:

```yaml
figures:
  enabled: true
  model: gpt-image-2
  audit_model: gpt-5.5
  base_url: https://your-image-endpoint.example/v1
  api_key: your-figure-api-key
```

The installed Autoillustrate version must support the image and audit model
identifiers, and the endpoint must support those models. `figures.enabled: false`
skips enhancement and visual API audits and keeps the agent's deterministic
export. Reviewer and figure credentials may differ from the shared coding
agent. `agsci doctor` checks the YAML credentials without printing them.
